# В обычном режиме — только edge, остальное — в diagnostic sweep при аварии

Статус: принято, 2026-10-03 (#100).

mon-client постоянно проверяет только edge-path'ы (все edge, active и standby): именно через них ходят пользователи. `direct` и `inner:*` проверяются только в diagnostic sweep — когда ни один edge-path типа inbound'а не в UP. Тогда mon-server с растущим интервалом (1 → 2 → 5 → 10 → 15 мин) проверяет все path и host reachability checks по цепочке и шлёт одно сводное уведомление при входе, изменении и выходе. `inner:*` вне обхода показывает derived state (edge-path проходит через это звено), `direct` — результат последнего обхода.

Межзвенный ICMP делает само звено (`x-ui proxy`) на каждом опросе цепочки, а результат едет к панели по тому же опросу и дальше в `GET /state`.

## Почему

- Постоянные пробы `direct` и `inner:*` давали алерты о путях, которыми пользователи из целевого региона не ходят (production 2026-10-03: `direct` лежал 2,5 часа при живых edge), и удваивали шум флапов.
- Нужны они только чтобы локализовать аварию — а это ровно момент, когда все edge лежат.

## Рассмотренные варианты

- **Пробы всех path без уведомлений по `direct`/`inner:*`** — меньше переделок, но та же нагрузка и те же ложные DOWN на странице.
- **mon-client на каждом звене** для межзвенного ICMP — единственный вариант, который отчитывается мимо цепочки и при полном обрыве, но это установка и токен mon-server на каждом edge (захваченный edge узнаёт адрес mon-server). Выбрали отчёт по опросу цепочки: он не раскрывает звеньям ничего нового, ловит частичные сбои (ICMP проходит, UDP/TLS режется), а полный обрыв плеча виден как «нет отчёта с HH:MM». Если в реальных авариях этого окажется мало — вернуться к mon-client на звеньях.
